# Design — test-movement-docs-aware

## Approach

The seam is the `changed_code` count inside `test_movement` in
`src/gate/g25.rs`. Today it counts every changed file that is not a test and
not incidental. Introduce a local `is_docs` predicate (markdown and plain-text
prose: `.md`, `.markdown`, `.mdx`, `.txt`, `.rst`, `.adoc`) and exclude those
files from the `changed_code` count, exactly as tests and incidental files are
already excluded.

Semantics preserved:
- code-with-no-test still blocks (docs excluded from the code count, but real
  source files are not);
- code-with-test still passes;
- a change of only docs now yields `changed_code == 0`, which takes the `pass`
  branch — the correct answer for a change with nothing to test.

The function keeps its signature and its return type, so none of the 15
importers in the blast radius are affected: they call G2.5, they do not depend
on this internal counting. New unit tests are added in the existing
`#[cfg(test)] mod tests` block in the same file — inside declared scope, so no
separate test file moves and the fix is self-contained.

## Blast radius (assessment)

The 15 dependents are importers of the gate pipeline, not of this heuristic's
internals. The change alters neither the function signature nor the verdict for
any case that exists today; it only reclassifies docs out of the code count.
The realised blast radius is one file: `src/gate/g25.rs`.
