# Design — runtime-contract

## Approach

The seam is the moment between `RunStart` and the agent, in both entry points
of `cmd/run.rs` (`run` and `run_waves`). A new `src/runtime/` module owns
`keel.posture/1` and exposes one call, `runtime::preflight(paths, cfg, slug,
run)`. It returns the `posture` `GateResult`, or `None` when nothing is
required.

`preflight`:

1. If `KEEL_RUNTIME_ATTESTATION` names a readable file, hash it and append an
   `attest` chain entry through `chain::record`: `sha256`, `runtime` and
   `properties` when it parses, and the hash alone when it does not (AC-1). This
   happens whether or not anything is required, so a runtime's claim is always
   on the record.
2. With `[runtime] require` empty, return `None`. Nothing else changes
   (AC-7).
3. Otherwise build the `posture` gate: an `attestation` check (blocked when
   unset, unreadable, or failing `schemas/posture.json` with the first
   offending field named: AC-5, AC-6), then one `posture:<name>` check per
   required property. `proven` → pass, `unproven` or absent → blocked,
   `violated` → fail (AC-2, AC-3, AC-4). `roll_up` gives the verdict, so
   fail beats blocked beats pass, as for every gate.
4. Write it to the run's gates dir. `GateResult::write` already chains it.

`cmd/run.rs` gains one helper, `posture_stop`, called right after `RunStart` in
both paths, before the prompt is built. It prints the gate. When the verdict is
not pass, it appends the `Gate` and `RunEnd` trajectory events, finishes the run
with that verdict, and returns the exit code (3 blocked, 1 fail), so no driver
is invoked. In `run_waves` that is before the first wave (AC-8).

The schema is embedded with `include_str!` and validated with `jsonschema`,
which is already a dependency, so a runtime author and keel read the same
contract.
