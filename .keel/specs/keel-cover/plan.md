# Design — keel-cover

## Approach

A new module, `src/cover/`, owns the content hash and the coverage decision.
G2 and the command are thin callers.

**Content hash (AC-2).** `cover::tree_hash(paths, cfg)`:
- Lists `git ls-files --cached --others --exclude-standard -z`, which is
  tracked plus untracked-but-not-ignored, the same set G2's diff sees.
- Drops paths under `.keel/` and the enabled adapters' rendered outputs (the
  same globs `g2::is_incidental_for` uses, minus lockfiles), and drops tracked
  files deleted from the working tree.
- Feeds each remaining path and its working-tree bytes, sorted by path, to
  `SetHasher`.

Because only working-tree bytes are read, it's the same hash committed, staged
or untracked. A symlink hashes its target path. The file mode isn't part of
the hash, which is a stated limit.

**G2 (AC-1).** It writes `tree.txt` to evidence next to `diff.patch`, from the
same call.

**Coverage (AC-3 to AC-6).** `cover::check(paths, cfg, exempt) -> Report`
hashes the head and considers each `.keel/bundles/*.tar.gz`, taking the first
reason that applies:
1. `keel bundle verify` doesn't pass: "failed verification", naming the
   failing checks.
2. The manifest's run verdict isn't `pass`: "run verdict <v>".
3. No `evidence/tree.txt` in the bundle: "predates tree hashes".
4. The hash differs: "a different tree (<12 chars>)".
5. Otherwise it covers the head.

The verdict is `covered` if any bundle covers the head, else `exempted` when
`--exempt` was given, else `uncovered`. Exit codes: 0, 0 and 1. A covered head
stays `covered` even with `--exempt`, because the stronger statement wins.

**Command and report (AC-7).** `keel cover [--exempt <reason>] [--json]`
prints the head hash and one line per bundle, or a `keel.cover/1` object
(`schemas/cover.json`).

**Action (AC-8).** A composite `action.yml` at the repository root. Its only
input is `keel-version`, defaulting to the first release that ships `keel
cover`. Its steps:
1. `actions/checkout` at `github.event.pull_request.head.sha`.
2. `cargo install keel-harness --version <v> --locked`.
3. `keel cover`, adding `--exempt "label keel:exempt"` when
   `contains(github.event.pull_request.labels.*.name, 'keel:exempt')`, passed
   through an env var, not interpolated into the script.

The test parses the YAML and asserts each of these.
