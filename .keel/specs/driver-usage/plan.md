# Design — driver-usage

## Approach

The seam is the driver result as it crosses from a driver into keel. Usage is
parsed once, in `src/driver/contract.rs`, as an optional `usage` object on
`keel.driverresult/1`; everything downstream consumes that typed value and
never re-reads driver output. `src/cmd/run.rs` hands each parsed result to the
trajectory, which records it as a `driver_usage` event through
`src/trajectory/event.rs` and `src/trajectory/mod.rs` with `source: reported`,
or `source: unreported` when the driver gave no usage. Reviewer usage from
`src/review/mod.rs` enters the same event attributed to `G2.5`.

Reporting reads only those events. `src/metrics.rs` totals spent tokens and
unreported calls apart from keel's estimated injected tokens,
`src/cmd/metrics.rs` prints the two as separate lines, and
`src/report/insights.rs` totals cost per spec including red runs. The price
table lives in `src/config.rs` and only fills in cost at read time, labelled
estimated. Spent and injected figures are never summed (ADR-0012, ADR-0020).

Tasks are chained because every one adds tests to `tests/driver_usage.rs`;
T-1 lands the usage type first and the rest build on it.
