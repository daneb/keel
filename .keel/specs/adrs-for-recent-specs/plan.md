# Design — adrs-for-recent-specs

## Approach

This is docs-only: three new Markdown files under `.keel/store/decisions/`,
three rows appended to the existing ADR index, and no change to any source or
test. The seam is the decision store: each ADR
is its own file, so the three can be written independently.

Each ADR follows `.keel/store/decisions/ADR-0020-*.md`: front matter with
`schema: keel.adr/1` and status `accepted`, then Context, Decision and
Consequences. Each must state what the shipped code does, read from `src/` and
the named tests rather than from memory, and must not revise the rule it
records:

- ADR-0026 (from `driver-usage`): spent tokens are reported by the driver,
  injected tokens are estimated by keel, and the two are never summed. Read
  `src/driver/contract.rs`, `src/trajectory/*`, `src/metrics.rs` and
  `tests/driver_usage.rs`.
- ADR-0027 (from `oracle-sensitivity`): sensitivity is native and blocking,
  mutation is a plugin and advisory. Read `src/gate/g2.rs`,
  `src/gate/oracle_exec.rs` and `tests/oracle_sensitivity.rs`.
- ADR-0028 (from `g3-human-judgement`): a human oracle is discharged per
  criterion and per run, and one merge approval no longer stands in for every
  judgement. Read `src/gate/g3.rs`, `src/approval.rs` and
  `tests/g3_judgement.rs`.

The one existing file touched is `.keel/store/decisions/ADR-0000-index.md`,
which changes by three appended table rows only (ADR-0026, ADR-0027, ADR-0028,
phase `field`, same format as the ADR-0025 row: `| [ADR-00NN](file.md) | field |
one-line decision |`). They go after the ADR-0025 row, before the "Not recorded
here" paragraph, with the blank line before that paragraph kept. The one-line
decisions come from the ADRs' own titles and Decision sections. Nothing else in
the index changes, including `verified_at`.

Ordering: T-1, T-2 and T-3 share no file and run in one wave. T-4 adds the
backing-test links to all three ADR files, so it depends on all three. T-6
edits only the index and depends on T-1, T-2 and T-3 for the file names and
decision wording; it shares no file with T-4, so T-4 and T-6 run in one wave.
T-5 runs `keel store check` after T-4 and T-6 and lists all four files because
it may have to correct one of them.

If a rule described in a spec differs from what the code does, the ADR states
the code's behaviour and the difference is reported, not papered over.
