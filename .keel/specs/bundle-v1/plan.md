# Design — bundle-v1

## Approach

Two seams: what goes into the archive (`evidence::export`), and a new verifier
module (`evidence/verify.rs`) that works on the archive's bytes alone.

**Patch (AC-3).** `diff::patch(paths, base)` returns `git diff --binary <base>`
plus a `git diff --no-index --binary /dev/null <file>` for each untracked file,
the same set `diff::against` measures. G2 writes it to evidence as `diff.patch`
next to `diff-stat.txt`.

**Chain in the bundle (AC-1, AC-2).** `export` takes an optional chain source.
It reads `--chain <file>` if given, otherwise `.keel/chain.jsonl`, and keeps
lines through the first `run_end` whose `data.run` is this run. If no such entry
exists, it keeps every line, and the verifier reports the missing `run_end`. The
kept lines become the `chain.jsonl` member. Their last hash goes in the manifest
as `chain_head`, an optional field added to `keel.manifest/1` and
`schemas/manifest.json` (additive only, as the spine freeze requires). With no
chain source there's no member and no `chain_head`.

**Verifier (AC-4 to AC-6).** `evidence::verify::check(archive) -> Report` reuses
`gate::Check` and `roll_up`, so its verdicts and exit codes mean what they mean
at every gate: 0 pass, 1 fail, 3 blocked. It runs these checks:

| check | fails when | blocked when |
| --- | --- | --- |
| `members` | a member is tampered, missing or unlisted (the existing `verify`) | no manifest |
| `chain` | an entry doesn't link, or the last hash isn't `chain_head` | no `chain.jsonl` |
| `approvals` | a stage's latest `approval` entry for this spec ≠ the hash of the shipped artefacts, naming the stage | no chain, or no approval recorded |
| `gate-verdicts` | a gate member (`gates/*.json`, `<slug>/gates/*.json`) has no `gate` entry with its SHA-256, naming the member | no chain |
| `trajectory` | no `run_end` for this run, or its `trajectory_sha256` ≠ the shipped `trajectory.jsonl` | no chain |

The chain check calls a new `chain::verify_str`, the walk `chain::verify`
already does, over text rather than a path. The approvals check calls a new
`approval::hash_named(stage, files)`, which `artefact_hash` is refactored to
use, so the recorded hash and the recomputed one come from the same code. It
maps each stage to the file names it covers: spec is `spec.md`; plan is
`plan.md` and `tasks.md`; merge is all three; review is `review-flags.txt`;
security is `security-findings.json`.

**Command (AC-7, AC-8).** `keel bundle verify <archive> [--json]` prints one
line per check, or a single `keel.bundleverify/1` object (`schemas/bundleverify.json`:
schema, archive, run, spec, verdict, checks), and exits with the verdict. It
never calls `Paths::discover` or reads config, so it has no dependency on a
repository, `$HOME` or the network. That's what AC-8 tests.
`keel export --verify` stays as it is.
