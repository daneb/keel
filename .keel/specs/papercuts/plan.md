# Design — papercuts

## Approach

Three small cuts, each at the one place its behaviour lives.

**`test-movement` (AC-1 to AC-3), in `gate/g25.rs`.** The seam is
`review-flags.txt`, which the review approval already hashes.
- `movement_flag(cfg, d)` is pure. It returns `test-movement: no test changed
  with <files>` when counted code changed and no counted test did.
- `test_invalidation` takes the movement flag as an extra line and writes it
  into the same flags file, including on its early-return path, where only the
  extra flag is written.
- `test_movement` passes, naming the reviewer, when the flag exists and the
  review standing is current. The flag names the files, so a different change
  alters the file, lapses the approval and blocks again. The block message now
  gives the `keel approve --stage review <slug>` command.
- The two unit tests move from `test_movement` to `movement_flag`.

**`keel cover` (AC-4), in `cover/mod.rs`.** `judge` says "verification
blocked" when the bundle's verify verdict is blocked, and "failed verification"
only when it failed.

**Drivers (AC-5), in `assets/drivers/*`.** A `# shellcheck disable=SC1091`
directive above each `_common.sh` source line, saying that file is checked on
its own. `-x` isn't assumed, because CI actions usually run without it.
