# Design — spec-summary

## Approach

`render()` is the seam: it already calls `renderSpine()` before switching on
`state.tab`. A new `renderSpecSummary()` slots in right after it, writing
into a new `#spec-summary` div placed between `#timeline-detail` and `.tabs`
in `index.html`.

1. `specSummary(spec)`: a pure aggregator — sums `tokens`/`events` across
   `spec.runs`; counts failing checks in `spec.gates` plus (if any runs
   exist) the last run's own `gates`; builds a `Map<gate, verdict>` by
   iterating `spec.gates` then every run's `gates` in existing (oldest-first)
   order, so the last write for a given gate id is its latest verdict.
2. `renderSpecSummary()`: a `.panel-section` with an `<h2>Summary</h2>`,
   reusing the existing `tile()`/`.tiles` grid (already styled, already used
   by the Overview page) for runs/tokens/events/open-fails, plus a new
   `.gate-badges` row of `.gate-badge` pills (one per entry in the gate map),
   coloured the same pass/fail/blocked way `verdictGlyph` already is.
3. CSS: `.gate-badges`/`.gate-badge` only — everything else reuses
   `.panel-section`/`.tiles`/`.tile` as they stand.
