# Design — runtime-fixes

## Approach

Both fixes are in `runtime/action.yml`. No Rust changes.

**gVisor (AC-1, AC-2).** A new input, `gvisor-version`, defaults to
`20260921.0`, the newest dated release. I checked that its `x86_64` folder
holds `gvisor.tar.zstd` and `gvisor.tar.zstd.sha512`, with `runsc` at the top
level of the tarball. The install step then:
1. Downloads both into a temporary directory.
2. Runs `sha512sum -c gvisor.tar.zstd.sha512`. The `.sha512` file names the
   tarball.
3. Runs `tar --zstd -xf gvisor.tar.zstd runsc`. The runners ship zstd.
4. Installs `runsc`, runs `runsc install`, and reloads Docker.

Any failure still falls back to runc, with the same warning. The version
reaches the script through `env`, never interpolated. AC-2's oracle checks
that the pinned release exists, so a pin that disappears fails the gate
rather than falling back quietly.

**No self-loop (AC-3).** A step right after checkout reads `git log -1
--format=%an` and `git diff --name-only HEAD~1 HEAD`. If the author is
`github-actions[bot]` and every changed path is under `.keel/bundles/`, it
writes `KEEL_SKIP=true` to `$GITHUB_ENV` and emits a notice. Otherwise it
writes `false`. Every later step carries `if: env.KEEL_SKIP != 'true'`.

**Tests** (`tests/runtime_fixes.rs`) parse the Action and check:
- the input's default
- the tarball and checksum URLs built from it
- that `sha512sum -c` runs before extraction
- that the version is passed through `env`
- the skip step's author and path test, and that it sits before the install
  steps
- that every step after it is guarded
