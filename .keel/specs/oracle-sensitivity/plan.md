# Design — oracle-sensitivity

## Approach

The seam is the oracle executor in `src/gate/oracle_exec.rs`, which G2
already calls to run one oracle against one tree. Sensitivity reuses it
unchanged against a second tree: `src/worktree.rs` creates a worktree at the
run's base commit and carries over the diff files matching
`[oracle] sensitivity_paths`, then `src/gate/g2.rs` calls the executor there
after the normal pass and compares outcomes. `src/spec/oracle.rs` gains the
`guard` prefix so the comparison knows which oracles are expected to pass at
the base. Mutation is a second, later call from `g2.rs` to an external command
(`[mutation] cmd`) whose stdout is validated against
`schemas/mutationresult.json`; keel never links a mutation tool, so the
`keel.mutationresult/1` contract is the only coupling. The cargo-mutants
adapter is an embedded asset written by `src/driver/builtin.rs` at `keel init`.

Sensitivity results go to `oracle-sensitivity.json` in the run's evidence and
into the `G2/oracle-sensitivity` check; an incomplete run reports `blocked`,
never `pass`. The existing test fixtures in `tests/support.rs` and
`tests/cover.rs` that assert behaviour already true at the base are tagged as
guards, so the new check does not fail them.
