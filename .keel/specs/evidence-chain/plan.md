# Design — evidence-chain

## Approach

The seam is the three places keel already persists evidence, not their
callers. A new `src/chain/` module owns `keel.chain/1`: entry shape, hashing,
append, sink and verify. Each existing writer gains one call to
`chain::record(near, kind, data)` after its own write succeeds:

- `approval::record` → `approval` (slug, stage, decision, artefact hash, by)
- `GateResult::write` → `gate` (gate, spec, run, verdict, SHA-256 of the
  written verdict file). Covers all four callers: `cmd/gate`, `cmd/run` ×2,
  `cmd/learn`.
- `Trajectory::append` → `run_start` / `run_end` only. `run_end` carries the
  SHA-256 of `trajectory.jsonl` after the event lands (AC-8); no other
  trajectory event reaches the chain. Covers all six start/end call sites
  in `cmd/run.rs` without touching them.

`record` finds the repo root by walking up from `near` to the nearest `.keel/`
ancestor, so no caller signature changes; with no `.keel/` above it (unit tests
in temp dirs) it does nothing. A chain write that fails fails the caller via
`?` — evidence that silently drops is worse than a loud error.

Per entry: redact the values of the env vars named in `[chain] secrets` from
`data` (AC-7), then:

- `KEEL_CHAIN_SINK` set: append `{kind, data}` as one line to the sink path
  and never open `.keel/chain.jsonl` (AC-5). The runtime stamps seq, time and
  hash on the host.
- unset: append a full entry to `.keel/chain.jsonl` with
  `writer: "in-process"` (AC-6).

The hash covers `prev_hash`, `seq`, `ts`, `kind`, `writer` and `data`, which is
Moor's `compute_hash` plus `writer`, so Moor can adopt the format by adding
one field. Genesis is 64 zeros, as in Moor.

`keel chain verify [--head <hash>]` walks the chain and names the first
entry whose `seq`, `prev_hash` or recomputed hash disagrees (AC-2, AC-3).
With `--head`, it fails when the last hash differs and prints both (AC-4).
Any in-process entry makes it print `self-attested`. `keel chain head` prints
the last hash. `schemas/chain.json` publishes the entry shape.
