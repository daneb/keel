# Design — pipeline-timeline

## Approach

`renderSpine()` in `assets/ui/app.js` is the seam: it already builds one
`.node` per `STAGES` entry from the already-served `SpecReport` (`stage`,
`gates`, `approvals`). No Rust or wire-format change is needed.

1. Turn each `.node` `div` into a `button` (native click/focus, matches the
   existing `.spec-row` and evidence-file buttons) carrying `data-stage`.
2. Add `#timeline-detail`, a single panel below `#spine` in `index.html`,
   toggled by `state.timelineOpen` (a stage key or `null`) the same way
   evidence rows already toggle a hidden `<pre>`.
3. A `stageDetail(spec, key)` function maps a stage key to its detail nodes:
   for `spec`/`plan_gate` it reads `spec.gates` for `G0`/`G1` and renders the
   verdict plus pass/fail/blocked counts via the existing `verdictGlyph`
   helper; for the three approval stages it reads
   `spec.approvals[stage]` and renders the standing (`current` with by/at,
   `absent`, `rejected` with note, or `superseded`); `plan`/`run`/`complete`
   fall back to the done/here/pending status the node's own CSS class already
   encodes, plus, for `run`, the latest run id and its G2 verdict when one
   exists.
4. `.spine .node::before` draws the connecting segment between a node and its
   predecessor (`:first-child` has none); `.node.done + .node::before` (and
   similarly for `.bad`) color the segment to match progress, so the track
   itself shows how far the journey has gone, not just each node in
   isolation.
5. `@media (max-width: 700px)` — the breakpoint `#rail` already stacks at —
   switches `.spine` from `flex-direction: row` to `column` and rotates the
   connector accordingly.
